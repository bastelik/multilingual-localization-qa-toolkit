# Terminology Management Workflow

Terminology management reduces ambiguity, protects product and institutional language, and helps teams produce consistent content across languages and contributors.

## 1. Identify terminology needs

Collect candidate terms from:
- Source content and recurring project vocabulary
- Product interfaces, help content and user documentation
- Client or institutional glossaries
- Subject-matter experts and authoritative domain references
- Previous approved translations and adjudicated review decisions

Prioritize terms that are frequent, brand-sensitive, domain-specific, ambiguous, legally significant or likely to affect user comprehension.

## 2. Research and propose equivalents

For each candidate, record the source term, context, part of speech, domain and proposed target equivalent. Check authoritative references and actual usage in the target locale. Do not select an equivalent solely because it is frequent: context and domain matter.

When a term has several plausible equivalents, document the alternatives and explain the recommendation. Preserve distinctions between related concepts rather than collapsing them into one convenient translation.

## 3. Approve and document

A practical terminology record can include:

| Field | Purpose |
|---|---|
| Source term | Canonical source-language form |
| Target term | Approved target-language equivalent |
| Locale | Specific target locale or language variant |
| Definition | Meaning in this project or domain |
| Context | Example sentence or usage note |
| Part of speech | Noun, verb, adjective, etc. |
| Status | Proposed, approved, deprecated or do not use |
| Source | Reference, client instruction or expert decision |
| Owner | Person or role responsible for approval |
| Date / version | Traceability and change control |

Keep the distinction between **approved**, **preferred**, **permitted**, **deprecated** and **prohibited** forms explicit.

## 4. Implement in production

- Make the current approved glossary accessible to translators, reviewers and relevant AI workflows.
- Identify terms that must remain unchanged, including product names, code, variables and trademarks.
- Provide context and grammatical guidance where a term's form changes by use.
- Check terminology during translation and independent review.
- Flag missing or conflicting entries instead of silently inventing policy.

## 5. Maintain the resource

When a new term or dispute arises:
1. Search the current glossary and prior decisions.
2. Check the project brief and source context.
3. Research reliable references.
4. Consult the designated subject-matter or terminology owner if needed.
5. Record the decision and rationale.
6. Update the glossary and notify affected contributors.
7. Review earlier content if the change has retroactive impact.

Do not overwrite an approved term without a traceable decision. Retain version history where possible.

## 6. Resolve terminology disputes

Use this order of consideration, adapting it to the project:
1. Explicit current client or product instruction
2. Approved project glossary and documented decisions
3. Applicable domain or regulatory terminology
4. Authoritative language references
5. Established target-locale usage
6. Reviewer preference

If two authoritative sources conflict, document the conflict and escalate it. The hierarchy should be agreed for the project rather than assumed.

## Lightweight terminology quality checks

- Is the term appropriate to the domain and context?
- Does it preserve the distinction in the source?
- Is it natural and correct for the target locale?
- Does it match the approved glossary?
- Is it used consistently across related strings and documents?
- Are capitalization, inflection and formatting rules respected?
- Is the term still current, or has it been deprecated?
